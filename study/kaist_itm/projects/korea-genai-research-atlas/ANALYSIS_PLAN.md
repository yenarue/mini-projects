# 과제 2 탐색 분석 확장 계획

## 1. 목적

기존 웹페이지의 규칙 기반 기술 주제 6개와 적용 영역 8개를 유지하면서, 사전에 정한 분류만으로는 보이지 않는 연구 간 관계를 추가로 탐색한다.

확장 분석은 다음 질문에 답한다.

1. 전체 과제와 연도별 과제에서 어떤 연구어가 자주 또는 특징적으로 나타나는가?
2. 제목·키워드·연구목표·연구내용이 유사한 프로젝트는 어떤 군집을 이루는가?
3. 각 군집의 대표 키워드·기관·적용 영역·연구비는 무엇인가?
4. 특정 프로젝트와 가장 유사한 다른 프로젝트는 무엇인가?

## 2. 분석 단위와 데이터 범위

- 분석 단위: 다년도 연차를 연결한 대표 프로젝트 1,151개
- 기간: 2023-01-01~2026-09-30
- 텍스트 입력:
  - 대표 과제명
  - 한글·영문 키워드
  - 연구목표요약
  - 연구내용요약
- 보조 변수: 연도, 기관, 지역, 연구비, 규칙 기반 기술 주제, 적용 영역
- 시리즈에 여러 연차가 있으면 포함 판정을 받은 연차의 중복되지 않은 텍스트를 합친다.
- 과제명은 연구의 중심을 보존하기 위해 텍스트 표현에서 가중치를 높인다.

## 3. 공개 원칙

- 연구목표·연구내용 원문은 분석에만 사용하고 웹 JSON·CSV에는 공개하지 않는다.
- 웹 공개본에는 다음 파생 결과만 추가한다.
  - 대표 키워드
  - 클러스터 ID와 사람이 읽을 수 있는 임시 이름
  - 2차원 좌표
  - 유사 프로젝트 ID와 유사도
- 연락처, 사업자번호, 내부 판정 로그는 계속 제외한다.
- 2차원 축 자체에는 학문적 의미가 없고 프로젝트 간 상대적 근접성만 해석한다.
- 클러스터는 공식 학문 분류가 아니라 탐색을 위한 데이터 기반 묶음으로 명시한다.

## 4. 분석 방법

### 4.1 텍스트 정규화

- Unicode NFKC 정규화
- 영문 소문자화
- HTML·제어문자·반복 공백 정리
- 한글·영문·숫자 토큰 보존
- `연구`, `개발`, `기반`, `활용`, `생성형 AI`, `인공지능`처럼 대부분의 문서에 반복되는 일반어는 별도 불용어로 관리한다.
- 원문은 수정하지 않고 분석용 텍스트만 별도로 생성한다.

### 4.2 키워드 분석

- 문서 빈도와 평균 TF-IDF를 함께 계산한다.
- 단일어와 2단어 구를 후보로 만든다.
- 전체 상위 키워드와 연도별 특징 키워드를 분리한다.
- 연도 비교는 과제 수가 아니라 해당 연도 프로젝트 내 문서 점유율을 사용한다.
- 2026년은 9월 30일까지의 YTD임을 모든 연도 비교에 표시한다.

### 4.3 유사도와 차원 축소

- 단어 1~2그램과 한글 띄어쓰기 변형에 강한 문자 3~5그램 TF-IDF를 결합한다.
- Truncated SVD로 고차원 희소 행렬을 축소한다.
- 프로젝트 간 유사도는 정규화한 벡터의 코사인 유사도로 계산한다.
- 각 프로젝트마다 자기 자신을 제외한 상위 5개 유사 프로젝트를 저장한다.
- 웹 시각화용 2차원 좌표는 고정 난수 시드로 생성하며 재실행 시 동일 결과를 보장한다.

### 4.4 클러스터링

- K-means 후보 `k=6~14`를 비교한다.
- 선택 기준:
  - 실루엣 점수
  - 지나치게 작은 군집 여부
  - 여러 초기값에서의 안정성
  - 상위 키워드와 대표 과제로 사람이 해석할 수 있는지
- 점수 하나만으로 k를 고르지 않고, 통계 지표와 해석 가능성을 함께 기록한다.
- 각 군집에 대해 대표 키워드, 대표 과제, 프로젝트 수, 정부 연구비, 상위 기관, 기술 주제·적용 영역 구성을 계산한다.

## 5. 검증 계획

### 데이터 일치성

- 프로젝트 수 1,151개와 `series_id` 고유값 1,151개가 일치해야 한다.
- 클러스터·좌표·유사 프로젝트가 없는 프로젝트가 없어야 한다.
- 유사 프로젝트 ID는 모두 공개 프로젝트 목록에 존재해야 한다.
- 자기 자신이 유사 프로젝트로 포함되면 안 된다.
- 기존 집계 수치와 연구비 합계는 분석 확장 전후가 동일해야 한다.

### 분석 품질

- 후보 k별 실루엣 점수와 군집 크기를 저장한다.
- 선택한 k는 여러 난수 초기값의 결과를 비교한다.
- 군집별 대표 과제 5개 이상을 표본으로 추출한다.
- 가장 유사한 프로젝트 쌍과 유사도가 낮은 프로젝트를 함께 점검한다.
- 키워드에서 일반어·검색어 자체가 결과를 지배하면 불용어를 조정하고 한 번만 재생성한다.

### 화면 품질

- 데스크톱·태블릿·모바일에서 키워드와 연구 지도 섹션을 확인한다.
- 1,151개 점을 표시해도 페이지가 멈추지 않아야 한다.
- 클러스터 선택, 프로젝트 선택, 유사 연구 표시, 초기화가 작동해야 한다.
- 키보드 탐색과 접근 가능한 설명을 제공한다.
- 브라우저 콘솔 오류가 없어야 한다.

## 7. 웹 화면 구성

기존 KAIST ITM 페이지의 글꼴, 색, 여백, 카드와 버튼 규칙을 그대로 사용한다. 기존 `무엇을 연구하는가`와 `프로젝트 탐색` 사이에 새 섹션을 추가한다.

### 탭 1. 키워드

- 전체·연도 선택 버튼
- 상위 특징 키워드 막대 또는 크기 비교
- 키워드별 문서 수와 전체 대비 비중
- 2026년 YTD 안내

### 탭 2. 연구 지도

- 점 1개가 대표 프로젝트 1개인 2차원 산점도
- 색상은 데이터 기반 클러스터
- 점 크기는 정부 연구비를 완만하게 변환해 표시
- 군집 선택 필터
- 프로젝트를 선택하면 상위 5개 유사 연구만 선으로 연결
- 우측 또는 하단 상세 패널에 과제명, 기관, PI, 대표 키워드, 유사 연구를 표시

### 탭 3. 군집 요약

- 군집별 프로젝트 수·연구비·대표 키워드
- 상위 기관과 적용 영역
- 대표 과제 3개

4. [완료] 클러스터 표본 검토와 임시 이름 확정
5. [완료] 상위 5개 유사 프로젝트와 2차원 좌표 생성
6. [완료] 분석 워크북·JSON·CSV 생성 및 검증

## 9. 중단 또는 재검토 조건

- 텍스트 결측 때문에 프로젝트 간 비교가 왜곡되는 경우
- 어떤 k에서도 군집이 지나치게 불균형하거나 대표 키워드로 해석되지 않는 경우
- 군집 안정성이 낮아 재실행마다 결과가 크게 달라지는 경우
- 제목만으로 계산한 결과와 연구목표·내용을 포함한 결과가 현저히 충돌하는 경우

이 조건이 발생하면 클러스터 수를 억지로 확정하지 않고, 키워드 분석과 유사 연구 탐색까지만 웹에 반영한다.
