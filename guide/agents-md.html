실전 AGENTS.md 예시 (React + TypeScript 프로젝트)

# AGENTS.md

## Project overview
E-commerce dashboard built with Next.js 14 + TypeScript.
Backend: Node.js, Prisma ORM, PostgreSQL.

## Tech stack
- Framework: Next.js 14 (App Router)
- Language:  TypeScript (strict)
- Styling:   Tailwind CSS + emotion css={{}} prop
- State:     MobX (useLocalStore)
- Charts:    ApexCharts only (no custom HTML tooltips)
- HTTP:      app/api/client.ts typed client

## Commands
npm install       # install deps
npm run dev       # dev server (use this for iteration)
npm run build     # production build (run outside agent session)
npm run test      # all tests
npm run lint      # eslint + tsc

## File-scoped checks
npm run tsc --noEmit src/foo.tsx
npm run eslint --fix src/foo.tsx
npx vitest run src/foo.test.tsx

## Project structure
- app/            → Next.js routes
- app/components/ → UI components
- app/lib/        → Utilities
- app/api/        → API client + routes
- prisma/         → Schema

Key files:
- App.tsx               → Root layout
- AppSideBar.tsx        → Navigation
- app/lib/theme/tokens.ts → Design tokens

## Code style
### Do
- TypeScript strict — no implicit any
- Functional components + hooks only
- Use emotion css={{}} for all styles
- Use design tokens from tokens.ts (no hardcoded colors)
- Small files and small diffs by default

### Don't
- Don't use class components (legacy: Admin.tsx)
- Don't hardcode colors (#fff, rgb(...))
- Don't add new dependencies without approval
- Don't refactor unrelated code in the same PR

## Testing
- Write tests as vitest functions (not class-based)
- Test file: same dir as source, *.test.ts
- Fix all errors before finishing

## Safety and permissions
Allowed without asking:
- Read / list files
- Single-file tsc, eslint, prettier
- Single vitest run

Ask first:
- npm install (new packages)
- git push, PR creation
- Deleting files
- Full build or e2e tests

✅ 해야 할 것

✓
간결하게 유지하기 — 이상적으로 150줄 이하. 에이전트는 매번 전체를 읽으므로 길수록 불필요한 컨텍스트 낭비
✓
명령어는 백틱으로 감싸기 — npm install, npm test 형태로 복사 즉시 실행 가능하게
✓
살아있는 문서로 관리하기 — 빌드 방법이 바뀌면 같은 PR에서 AGENTS.md도 함께 업데이트
✓
모노레포엔 계층형 구조 — 루트 AGENTS.md + 각 패키지 내부에 별도 AGENTS.md, 가장 가까운 파일이 우선 적용
✓
구체적인 파일 예시 제공 — "함수형 컴포넌트 참고: Projects.tsx" 처럼 좋은 패턴 / 나쁜 패턴 파일 직접 언급
✓
점진적으로 성장시키기 — 처음엔 작게 시작, 에이전트가 실수할 때마다 해당 항목 추가

❌ 하지 말아야 할 것

✕
코드 스타일을 과도하게 나열하지 않기 — 린터가 할 일을 에이전트에게 시키면 컨텍스트 낭비. ESLint, Prettier 활용
✕
파일 경로를 과도하게 문서화하지 않기 — 경로는 자주 바뀜. "어디에 있다"보다 "어떤 기능을 한다"로 설명
✕
README와 중복하지 않기 — 이미 README에 있는 내용을 반복하지 말 것
✕
지나치게 자세히 쓰지 않기 — 오래된 정보가 에이전트를 잘못된 방향으로 유도. LLM이 안정적으로 따를 수 있는 지침은 150~200개 수준
✕
모든 가능한 명령을 다 넣지 않기 — 항상 관련 있는 내용만, 컨텍스트 윈도우는 유한
